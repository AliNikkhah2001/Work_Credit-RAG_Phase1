  • Client layer — The user-facing tier containing the browser and Open WebUI interface.
  • Browser — The end user's web browser accessing Open WebUI.
  • Open WebUI :13000 rag_trace_capture filter X-Request-ID sticky thread — The chat frontend on port 13000 with the rag_trace_capture filter that captures filter_path, injects X-Request-ID, and maintains sticky conversation threads.

  • api.py create_app POST /v1/chat/completions — The FastAPI application entry point exposing the OpenAI-compatible chat completions endpoint.
  • graph.py rag_graph MemorySaver checkpointer — The LangGraph state graph definition with MemorySaver for persistent conversation state.
  • validate_input — Graph node that validates user input through guardrails input rails.
  • classify — Graph node that classifies queries as greeting, specification, or question.
  • hybrid_classify — Graph node that applies SVM-RBF hybrid classification for query routing (when enabled).
  • retrieve — Graph node that queries the knowledgebase for relevant document chunks.
  • build_context — Graph node that assembles retrieved chunks into a bounded context window.
  • guarded_generate — Graph node that requests safety-guarded generation from Guardrails.
  • format_response — Graph node that formats the final answer with citations and follow-ups.
  • format_refusal — Graph node that formats refusal messages for blocked inputs.
  • generate_clarification — Graph node that generates clarification questions for ambiguous queries.
  • Knowledgebase :8000 kb_manager — The retrieval service on port 8000 managing the document index.
  • web/app.py app POST /search/api POST /search/supplement — The KB FastAPI app exposing search and supplement endpoints.
  • web/routes/search.py BM25 tantivy dense MiniLM-384 RRF k=60 bge-rerank pgvector HNSW 1123 chunks — The search pipeline implementing BM25 keyword search, dense MiniLM-384 embeddings, Reciprocal Rank Fusion with k=60, bge-reranker cross-encoding, pgvector HNSW index over 1123 chunks.
  • filter_path folder_hierarchy — Path-based and tag-based filtering mechanisms for scoping retrieval to specific document subspaces.
  • Guardrails :8200 work_rag_guardrails — The safety service on port 8200 implementing Persian safety policies.
  • api.py service.py create_app POST /v1/rails/check POST /v1/chat/completions — Guardrails FastAPI app with input rail checking and guarded chat completions.
  • service.py judge signals LLM judge UPSTREAM Gemma :18000 :9000 — The LLM judge service using deterministic signals plus Gemma-based judgment, calling upstream Gemma on :18000 (self-hosted) or :9000 (H200 manager).
  • LLM Manager :9000 llm_inference_manager/app.py — The LLM inference gateway on port 9000 managing multiple model backends.
  • MODEL_REGISTRY 11 models gemma-4-31b champion — The model registry containing 11 registered models with gemma-4-31b as the champion model.
  • uvicorn :9000 proxy_chat backends 8080-8084 — The uvicorn server on port 9000 proxying chat requests to llama.cpp backends on ports 8080-8084.
  • Observability — The tracing and monitoring infrastructure.
  • Collector :3000 observability.db SQLite — The fallback trace collector on port 3000 storing traces in SQLite.
  • Langfuse v2 :3001 — The Langfuse v2 tracing backend on port 3001.
  • Studio :2024 LangGraph API — The LangGraph Studio API on port 2024 for graph debugging.
  • Browser → WebUI — The user's browser loads the Open WebUI interface.
  • WebUI → API — Open WebUI forwards requests to the orchestrator API.
  • API → GRAPH — The API routes requests into the LangGraph state graph.
  • GRAPH → VI — The graph starts execution at the validate_input node.
  • VI → blocked → RF — If input is blocked, execution goes to format_refusal.
  • VI → allowed → CL — If input is allowed, execution proceeds to classify.
  • CL → greeting spec → FR — Greetings and specifications bypass retrieval and go to format_response.
  • CL → question → RET — Questions proceed to the retrieve node.
  • RET → SEARCH — The retrieve node calls the KB search API.
  • SEARCH → FILTER — Search results are filtered by path and folder hierarchy.
  • RET → continue → BC — Retrieved results continue to context building.
  • BC → GG — Built context is passed to guarded generation.
  • GG → GJUDGE — Guarded generation calls the LLM judge for safety validation.
  • GJUDGE → MR — The judge queries the model registry for the upstream LLM.
  • GRAPH →. Coll — The graph asynchronously sends trace data to the collector.
  • Coll → LF2 — The collector forwards traces to Langfuse.
  • Coll →. Studio — The collector also connects to LangGraph Studio.

  • Orchestrator → WebUI: abstain no citations — If evidence score is below 0.15, the system abstains with no citations.
  • Orchestrator → Guardrails: POST /v1/chat/completions guarded_generate — If evidence exists, guarded generation is requested.
  • Guardrails → LLM Manager: llama-server /v1/chat/completions — Guardrails forwards to llama-server for generation.
  • LLM Manager → Guardrails: raw answer — The raw model answer is returned.
  • Guardrails → Orchestrator: {answer guardrail_output} — Guardrails returns the answer with guardrail output metadata.
  • Orchestrator → Orchestrator: format_response citations grounded follow_ups — The final response is formatted with citations, grounded follow-ups, and supplemental data.
  • Orchestrator → Collector: trace-create upsert output audit — The output trace is upserted with audit information.
  • Orchestrator → WebUI: {choices[0].message.content rag:{citations supplemental follow_ups} audit} — The final response with message content, RAG data, and audit is returned.

Request Lifecycle

  1. WebUI filter (components/openwebui-filters/rag_trace_capture.py) — captures filter_path from scope/[چک] prefix, injects X-Request-ID, records trace start.
  2. validate_input — Guardrails input rails; short-circuits to refusal if blocked.
  3. classify + infer_specification — classifies greeting/spec/question; maps query to applied_subspace via subspace_map; general exempt from clarify gate.
  4. should_clarify? — scattered/ambiguous query with no resolved subspace → generate_clarification returns finish=clarify with available subspaces, no KB call.
  5. retrieve — POST /search/api with rewritten query, top_k=20, filter_path (explicit or sticky). KB returns SearchSteps + injected_entities. Parallel POST /search/supplement (threshold 0.4) for entity lists.
  6. build_context — MAX_CHUNKS=20, MAX_CONTEXT_CHARS=9000; evidence guard per-subspace (cheque 0.05, facilities_person 0.10, facilities_legal 0.15, general 0.15) — below threshold → abstain.
  7. guarded_generate — Guardrails :8200 → Gemma :18000 (enable_thinking:false, --no-mmproj --jinja).
  8. format_response — citations ≤20, rag.supplemental, grounded follow_ups, stage_timing_ms.
  9. Observability — async trace to :3000 (observability.db) + Langfuse :3001; DLQ /tmp/dlq_retrieval.jsonl on empty filtered retrieval.

subspace_map: cheque → گزارش اعتبارسنجی چک, facilities_person → اشخاص حقیقی/اعتبارسنجی تسهیلات, facilities_legal → اشخاص حقوقی/اعتبارسنجی تسهیلات, general → پایگاه دانش عمومی.

filter_path travels WebUI filter → Orchestrator → KB and sticks via X-Request-ID thread until re-specified (چک re-spec switches subspace).
