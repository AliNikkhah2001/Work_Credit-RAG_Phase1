Problems

Detailed breakdown of each multi-turn RAG problem with root cause analysis

Context: Production system serving Persian credit-scoring QA across 4 subspaces (cheque, facilities_person, facilities_legal, general) with 1123 chunks over 18 documents. Benchmark: 41 turns (12 multi-turn + 12 single) across 4 subspaces.

🔍 Subspace Filtering Failure

Impact: 0-chunk retrieval despite relevant content | Fix: Map correction + RRF fusion

Static subspace_map had "cheque": "چک" but KB folders used "گزارش اعتباراتنجی چک". The filter "چک" matched zero chunks because KB filter checks exact element membership in folder_hierarchy, not substring.

Root CauseMap MismatchPC-RAG

❓ Ambiguity Resolution Failure

Impact: 6/6 scattered queries answered instead of clarifying | Fix: Retrieval-grounded clarification + iterative loop

Queries like "وضعیت اعتباری چطور است" (credit status how is it) and "بدهکار شدم چیکار کنم" (I became debtor what to do) are scattered across subspaces. System answered "پاسخی یافت نشد" instead of clarifying with "چک / تسهیلات / شرکت" pills.

Root CauseKeyword GateRAC

🔗 Sticky Context Decay

Impact: Context lost after 3-4 generic turns | Fix: Sticky carry + decay after 3 generic turns

After explicit subspace selection "چک" → applied_subspace=cheque, follow-up "تاثیر چک برگشتی..." lost sticky (became None). Generic follow-ups like "آیا درآمد..." didn't carry filter_path.

Root CauseDecayCPP

📉 Retrieval Degradation

Impact: Filtered retrieval = hard filter, no fallback | Fix: RRF fusion + broadened retry + GPU

Filtered retrieval was treated as authoritative with NO fallback. When filter_path returned weak scores (<0.15), chunks cleared → abstention. No whole-KB fallback, no broadened params, no GPU.

Root CauseNo FallbackGUIR

🛡️ Hallucination Control

Impact: Weak-evidence answers hallucinated | Fix: Coverage+score guard + lexical bypass

Answers on weak evidence (fallback/broadened paths) hallucinated. G5 fake grade was correctly refused, but other weak-evidence answers invented facts. Hallucination rate 0.195 → 0.254 (tradeoff for recall).

Root CauseDUTIRFaith Guard

⚡ CPU Latency Bottleneck

Impact: Dense embed 2.3s dominated latency | Fix: GPU embed + rerank pool 30

KB search: dense 2325ms (99.5% of search time). Rerank was 1.1ms (not bottleneck!). GPU: dense 19ms (100×), rerank 52ms (real BGE-m3 scores), total 2333ms → 70ms.

Root CauseCPU EmbedGPU KB
